# GPGPUCPU

VM Filter Palette（GPUミニ仮想機械）

UnityのCompute Shader上で動作する、ピクセル単位の**ミニ仮想マシン（VM）**です。  
各ピクセルが16bit命令セットで構成された小さなプログラムを実行し、最大256種類のプログラムを「パレット方式」で選択できます。

ジャンプ抑制トグル（DisableJumps）により、インスペクタ上で「安定モード」と「カオスモード」を切り替えることが可能です。

---

## 🧩 1. 基本構造とアーキテクチャ

各ピクセルは独立したスレッドとしてVMを実行します。  
命令列は `Bytecode` バッファ内に格納され、`Programs` テーブルでスロットごとの範囲を管理します。

### 構成要素

| 要素 | 種類 | 説明 |
|------|------|------|
| **レジスタ** | `r0..r3`, `R,G,B` | 8bit作業レジスタ |
| **フラグ** | `Z` | Zeroフラグ（結果が0の時にセット） |
| **プログラムカウンタ** | `pc` | 現在命令位置 |
| **Programsテーブル** | `offset,length` | 各スロットの範囲を指定 |
| **Bytecode** | 16bit列 | 命令本体 |
| **MaxSteps** | 定数 | 実行上限（無限ループ防止） |
| **DisableJumps** | 定数 | 0=ジャンプ許可, 1=抑制 |

### 実行の流れ

```
各ピクセルについて:
  idx = IndexTex(x,y).r
  該当スロットのプログラムをロード
  r0..r2 = 入力RGB
  r3 = 座標seed
  MaxSteps 回まで命令を実行
  OUT または 終端で停止
  出力色 (R,G,B)/255 を書き込む
```

## ⚙️ 2. 命令セット一覧

命令は16bit固定長（`OOOO AAAA IIIIIIII`）です。  
- `O`: 4bit オペコード  
- `A`: 4bit レジスタ選択  
- `I`: 8bit 即値または選択子  

| Opcode | Mnemonic | オペランド | 内容 |
|--------|-----------|-------------|------|
| 0x0 | **NOP** | — | 何もしない |
| 0x1 | **LDI A, imm** | 即値 | 即値をロード |
| 0x2 | **ADD A, imm** | 即値 | 加算 |
| 0x3 | **XOR A, imm** | 即値 | XOR演算 |
| 0x4 | **ROTL A, imm** | 即値 | 左ローテート |
| 0x5 | **MIX ACC, A** | レジスタ | R,G,Bへ混合 |
| 0x6 | **MOV A, sel** | レジスタ | コピー |
| 0x7 | **ADDR A, sel** | レジスタ | 加算（他レジスタ） |
| 0x8 | **XORR A, sel** | レジスタ | XOR（他レジスタ） |
| 0x9 | **TSTZ A** | — | Zeroフラグ更新 |
| 0xA | **JZ off** | 相対 | Z=1ならジャンプ |
| 0xB | **JNZ off** | 相対 | Z=0ならジャンプ |
| 0xC | **JMP off** | 相対 | 無条件ジャンプ |
| 0xD | **ACCW A, mask** | mask(1:R,2:G,4:B) | 色チャンネルへ書込 |
| 0xE | **HASH A** | — | 非線形ハッシュ変換 |
| 0xF | **OUT** | — | プログラム終了 |

## ✨ 3. 特徴

- GPU上で完結する軽量VMアーキテクチャ  
- 256スロットのプログラムパレット  
- ジャンプ抑制トグルで安全化またはグリッチ化を制御  
- ステップ上限設定による実行時間管理  
- `.asm`→バイトコード変換アセンブラを同梱  
- メモリアクセス不要・完全サンドボックス実行

## 🎛️ 4. Unity設定方法

1. プロジェクトにファイルを導入  
2. 任意のGameObjectに `FilterPaletteDemo.cs` を追加  
3. 次を設定：
   - `SourceTex`：入力画像  
   - `IndexTex`：スロット指定画像（R=0〜255）  
   - `BytecodeHex`：`out/bytecode.hex`  
   - `ProgramsJson`：`out/programs.json`  
4. 再生して実行  

インスペクタ操作：  
- **DisableJumps**：ジャンプ命令の抑制ON/OFF  
- **MaxSteps**：実行上限（64〜128推奨）

## 📦 5. アセンブル手順と生成物

新しいビジュアルエフェクトを作成する際は、人間が編集しやすいテキスト資産と、Unityが直接読み込む生成物をアセンブラで往復します。

- `*.asm`（例: [`asm-samples/`](asm-samples/) 内のファイル）は人間が記述するソースです。各行には命令セットのニーモニックとオペランド、コメント、ラベルなどを記述します。新規エフェクトはここを編集します。
- `out/programs.json` はアセンブル時に生成される256エントリの配列で、各スロットのバイトコード開始位置 (`offset`) と命令数 (`length`) を含みます。Unity側はこの情報を参照して、どのパレットインデックスにどの命令列が割り当てられているかを判断します。
- `out/bytecode.hex` には16bit命令が `0xOOOO` 形式で1行ずつ出力されます。このファイルはCompute ShaderからそのままGPUバッファへコピーされるため、バージョン管理や手動での微調整が容易です。

アセンブラを実行すると `.asm` ソースからこれら2つの出力が同時に更新され、メタデータと命令列が常に同期した状態になります。

## 🎨 7. アート用途

任意のバイト列を命令列として入力可能です。  
テクスチャやノイズデータをコードとして解釈させることで、生成的・グリッチ的なビジュアルを作り出すことができます。
